# 보고서 공방 · HWPX Studio

공공기관 업무보고를 위한 **개인용 로컬 웹앱의 실행 가능한 초기 버전**입니다.
보고 목적에 맞는 구성안을 만들고, 근거를 연결하고, 부품을 편집한 뒤 편집 가능한 문단·표 중심의 HWPX를 생성합니다.

Python + FastAPI + SQLite + 순수 JavaScript로 구성했습니다. Node.js 빌드나 외부 AI 계정 없이 기본 기능을 사용할 수 있습니다.

## 바로 실행

Windows에서 **`start.bat`를 더블클릭**합니다. Python 3.11 이상이 필요합니다.
첫 실행은 프로젝트의 `.venv`에 패키지를 설치합니다. 설치를 마치면 브라우저가 열립니다.

- 앱: [http://127.0.0.1:8765](http://127.0.0.1:8765)
- API 문서: [http://127.0.0.1:8765/docs](http://127.0.0.1:8765/docs)
- 종료: 서버 터미널에서 Ctrl+C
- 이미 실행 중이면 새 서버를 띄우지 말고 위 주소를 엽니다.

직접 실행:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py
```

다른 포트: `run.py --port 8766`. 브라우저를 자동으로 열지 않으려면 `--no-browser`를 붙입니다.
설치 후에는 패키지 설치를 반복하지 않고 `.venv\Scripts\python.exe run.py`만 실행해도 됩니다.

## 사용 순서

1. **내용 입력 → 추진계획서**에서 보고요지·추진배경·목표·단계별 절차·일정·예산·기대효과 등을 직접 작성합니다. 입력한 항목만 자동 구성하여 새 문서로 저장합니다. 다른 목적은 **새 보고서**를 이용합니다.
2. 왼쪽 **근거자료**에서 TXT, MD, CSV, JSON, HWPX의 텍스트를 가져오거나 직접 붙여 넣습니다. 양식 참고용과 사실 근거용, 내부자료와 공개자료를 구분합니다.
3. 부품을 선택해 본문, 표, 절차, 그래프 데이터를 입력하고 관련 근거를 연결합니다. 자료의 출처 위치·기준시점을 입력하고 원자료를 대조한 뒤 검토 완료를 표시합니다.
4. 순서와 필수 부품을 확인하고 **구성안 확인 완료**를 누릅니다.
5. 오른쪽 **검토**에서 누락·수치·출처 오류를 해결합니다. 오류가 있어도 검토용 초안 생성은 가능하지만 잘못된 표 구조 등으로 파일 내용이 유실될 경우 출력 엔진이 거부합니다.
6. **HWPX 내보내기**로 초안을 받아 실제 한글에서 확인합니다. 구버전 한글에서 오류가 발생하면 **한글 2014용 HWP**로 내보냅니다. HWP는 설치된 한글로 생성 후 다시 불러와 내용을 대조합니다. 한글 PDF 변환이 설정되어 있으면 검토 탭에서 실제 렌더링 PDF를 볼 수 있습니다.
7. 원자료와 실제 HWPX 배치 검토를 마친 사용자가 이름과 확인 항목을 입력해 **최종 승인**합니다. 이후 변경은 승인을 해제합니다.

예시 자료는 전부 가상 데이터입니다. 예시라는 표시는 삭제할 수 없습니다. 실제 업무용 문서는 새로 작성하세요.
저장은 각 편집기의 **변경사항 저장** 버튼으로 수행합니다. 저장하지 않은 입력은 부품 전환 시 유지되지 않습니다.

## 직접 입력하여 추진계획서 만들기

상단 **내용 입력 → 추진계획서**를 선택합니다. 내용은 자동 요약하거나 새로 지어내지 않고, 입력한 항목에 맞게 배치합니다.

- **단계별 추진 절차**: 한 줄에 한 단계. 최대 40단계.
- **추진배경·목표·기대효과**: 한 줄에 한 항목. 긴 문장은 본문으로 보존.
- **추진일정**: 자유 서술 또는 `시기 | 추진내용 | 담당` 형식. 제목행 없이 한 줄에 한 행.
- **소요예산**: 자유 서술 또는 `항목 | 금액 | 산출근거` 형식. 금액의 단위를 직접 입력.
- **사실 확인 체크**: 사용자가 원자료를 확인한 경우에만 선택. 선택하지 않아도 초안 작성·내보내기가 가능.
- 작성창을 닫고 다시 열면 입력 중인 내용이 남아 있습니다. **브라우저 새로고침 전에는 계획서 만들기를 눌러 저장하세요.**

입력 예시:

```text
[추진 절차]
대상 선정 및 사전 협의
현장 조사
성과 검토
결과 보고

[추진일정]
10월 | 현장 조사 | 조사팀
11월 | 성과 검토 | 검토팀
```

0.2의 기본 HWPX 출력은 도형을 사용하지 않습니다. 미리보기 텍스트·문서 제목·작성자·커서 정보도 새 보고서에 맞게 정리합니다. **이전에 다운로드한 파일은 변경되지 않으므로 새로 내보내야 합니다.** 저장해 둔 보고서 내용과 수정 이력은 유지됩니다.

한글 2014에서 R6025가 발생한 PC에는 HWP 버튼을 함께 제공합니다. 한컴은 HWPX 하위 호환성 대응이 2014 VP부터 반영되었다고 안내합니다. 앱의 호환성 조정만으로 모든 구버전의 HWPX 필터 오류를 보장할 수는 없습니다. [한컴 HWPX FAQ](https://www.hancom.com/support/faqCenter/faq/detail/2784)

### 현재 한계

- **임의의 기관 양식 전체를 복제하는 엔진은 아닙니다.** 머리말, 로고, 복잡한 병합표, 다단 배치, 기존 도형 위치, 여러 구역의 서로 다른 스타일은 복제하지 않습니다. 추출한 스타일 값을 적용한 새 문서를 만듭니다.
- 웹 미리보기와 쪽수는 **계산에 따른 예상치**입니다. 글꼴 설치 상태와 한글 조판에 따라 실제 배치가 다를 수 있습니다. 자동 잘림 판정도 높이 추정에 한정합니다.
- 구버전 호환성을 높이기 위해 절차·전략은 **편집 가능한 표**, 그래프는 수치와 문자 막대를 담은 표로 출력합니다. 네이티브 차트 개체가 아니며 그래프 원자료는 앱에서 수정·재생성합니다.
- 숫자 검사는 연결 자료에 같은 숫자 문자열이 있는지 대조합니다. **수치의 의미, 단위 일치, 합계·계산식, 사실의 진실성까지 입증하지 않습니다.** 비수치 사실도 사용자가 확인해야 합니다.
- 자동 구성은 규칙 기반입니다. 예산·일정·전략을 새로 지어내지 않습니다. 기관장용 문서의 설명 순서를 자유롭게 추론하는 전체 문서 AI 기획기는 후속 범위입니다.
- PDF/이미지의 OCR, 사진 삽입 편집, PPTX 출력, 외부 한글 수정본과 앱 데이터의 자동 병합은 미구현입니다.
- 공동 사용자 인증·권한·전자결재는 없습니다. 승인과 잠금은 개인 작업 흐름을 위한 기능이며 법적 전자서명이 아닙니다.
- 저장소는 로컬 일반 SQLite입니다. 기관 공용 운영 전에는 별도의 인증, 권한, 암호화, 백업과 배포 검토가 필요합니다.

## 부분 수정 명령

기본 로컬 모드에서는 다음 명령만 처리합니다. 해석할 수 없는 요청을 임의로 실행하지 않습니다.

```text
제목: 추진절차 및 역할
본문: 사용자가 확인한 새로운 본문
단계: 대상 선정 / 현장 촬영 / 영상 제작 / 성과 검토 / 납품
맨 앞으로
맨 뒤로
개조식으로
```

잠긴 부품은 먼저 별도로 잠금을 해제해야 수정할 수 있습니다. 연결된 원자료도 함께 보호합니다.
필수 부품을 삭제하려면 먼저 필수 표시를 해제합니다. 이전 버전 복원 역시 현재 잠금 정책을 따릅니다.

## 선택형 AI 문장 다듬기

AI를 사용하지 않아도 보고서 작성·출력이 가능합니다.
AI 연결은 [OpenAI Responses API의 Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)를 사용합니다.

서버를 실행할 PowerShell 세션에서 환경 변수를 설정하세요.

```powershell
$env:OPENAI_API_KEY = "본인의 API 키"
$env:OPENAI_MODEL = "계정에서 사용 가능한 Structured Outputs 지원 모델 ID"
.\.venv\Scripts\python.exe run.py
```

`.env` 파일은 자동으로 읽지 않습니다. API 키는 브라우저로 전달하지 않습니다.

편집 화면에서 AI 옵션과 **이번 전송 동의**를 선택하면 선택 부품의 제목·본문·항목, 수정 요청, 연결된 공개 근거의 내용·시점만 전송합니다. 확인되지 않은 자료나 내부·양식 자료가 연결된 부품은 거부합니다. AI는 제목·본문·항목만 제안하며 표·그래프 숫자와 잠금·출처 연결을 바꿀 수 없습니다. 수치 집합이 달라진 응답은 거부합니다.

API 응답에 `store: false`를 지정합니다. 이 옵션이 외부 전송 자체를 없애는 것은 아닙니다. 실제 기관 자료의 공개 여부는 사용자가 판단해야 합니다. 변경 결과는 검토 전 초안이며 기존 승인이 해제됩니다.
API 키 없이 개발했으므로 실제 유료 API 호출은 검증하지 않았습니다. 전송 차단과 응답 검증은 테스트합니다.

## 선택형 실제 한글 PDF 변환

Windows에 한글이 설치되어 있고 COM 자동화가 허용되는 환경에서만 동작합니다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-windows-pdf.txt
.\.venv\Scripts\python.exe run.py
```

검토 탭의 **한글에서 PDF 렌더링·보기**는 생성된 HWPX를 별도의 한글 인스턴스로 열어 PDF로 저장합니다. 브라우저 화면을 PDF로 인쇄해 실제 HWPX 렌더링으로 표시하지 않습니다.

관리자가 승인·설치한 파일 접근 보안모듈이 있는 경우에만 등록 이름을 지정할 수 있습니다.

```powershell
$env:HWP_SECURITY_MODULE = "기관에서 등록한 모듈 이름"
```

프로그램은 보안모듈을 다운로드하거나 레지스트리를 변경하지 않습니다. 파일 접근 확인창, 한글 설치·라이선스, 자동화 정책으로 열기가 막히면 55초 후 오류를 표시합니다.

**개발 PC의 한글 2014(9.0.0.562)에서 HWP 생성·메모리 재열기·문자열 대조를 확인했습니다. HWPX Open/SaveAs 및 이미지 생성은 시간 초과하여 HWPX의 실제 열림·시각 배치·PDF 품질은 미검증입니다.** 구버전에서는 HWP 출력을 권장하며, HWPX R6025의 정확한 원인과 완전 해소를 확정한 것은 아닙니다.

## JSON → HWPX 일괄 생성

```powershell
.\.venv\Scripts\python.exe -m app.cli --input examples/drone-report.json --output outputs/report.hwpx --strict
```

`--strict`는 근거·수치 검증 오류가 있으면 출력을 중단합니다. 경고는 출력하며 파일을 생성합니다.
CLI 출력은 항상 초안입니다. 사용자 양식 프로필 JSON은 `--profile profile.json`, 선택형 PDF 경로는 `--pdf outputs/report.pdf`로 지정합니다.

- 예시 데이터: [examples/drone-report.json](examples/drone-report.json)
- 생성 예시: [examples/drone-report.hwpx](examples/drone-report.hwpx)
- 모델 정의: [app/models.py](app/models.py)

```text
  validation.py   근거·수치·구조·예상 높이 검사
  exporter.py     네이티브 HWPX 객체 조립과 재검증
  editing.py      잠금 정책, 로컬 명령, 선택형 AI
  storage.py      SQLite 저장·버전·동시수정 제어
  pdf.py          선택형 한글 COM 변환 실행·타임아웃
  pdf_worker.py   별도 프로세스에서 한글 열기·PDF 저장
  main.py         로컬 API와 웹 파일 제공
  cli.py          일괄 출력 명령
  static/         한국어 3영역 편집 화면
tests/            출력·자료·잠금·승인·업로드 회귀 테스트
examples/         재현 가능한 가상 예시
```

데이터는 `data/reports.sqlite3`에 저장됩니다. 앱을 종료한 상태에서 `data` 폴더를 복사하면 백업할 수 있습니다.
`REPORT_DATA_DIR` 환경 변수로 저장 경로를 바꿀 수 있습니다.
`data`, `outputs`, `.venv`, API 키 파일은 Git 추적 대상에서 제외했습니다.

API 변경 요청에는 `X-Report-Client: studio-v1` 헤더가 필요합니다. 서로 다른 사이트에서 들어오는 변경 요청을 차단합니다.
서버는 기본적으로 `127.0.0.1`에만 바인딩합니다.

## 검증

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
node --check app/static/app.js
```

자동 테스트는 목적별 구성, 자료 구분, 숫자 누락, 그래프 오류, 잠금 우회, 필수 부품, 내부자료 외부 전송 차단, 긴 본문·많은 표 행·다단계 절차의 보존, HWPX 스키마와 재개봉, 스타일 추출, ZIP 경로·XML 엔터티, 버전 충돌·복원, 승인 무효화를 확인합니다.

실제 브라우저에서 예시 열기, 절차 변경, 변경 비교, 잠긴 예산표, 이력 복원, 데스크톱·모바일 표시와 콘솔 오류를 확인했습니다. 내보내기 API의 HWPX 응답은 검증했지만 자동화 브라우저의 파일 저장은 ‘다운로드 오류’로 완료하지 못했습니다.
